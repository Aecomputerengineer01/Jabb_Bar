## 1. แผนภาพ ER Diagram (Mermaid ERD)

ฐานข้อมูลของร้านจ๊าบบาร์บน PostgreSQL ได้รับการออกแบบให้รองรับทั้ง **การนับสต็อกแบบปัจจุบัน (Current Operational State)** และ **การบันทึกประวัติการปิดยอดในอดีต (Historical Snapshots)** เพื่อให้เจ้าของร้านสามารถตรวจสอบย้อนหลังได้ทุกวัน:

```mermaid
erDiagram
    DrinkItem ||--o{ ShiftRecord : "บันทึกประวัติลงใน"
    DailyShift ||--|{ ShiftRecord : "ประกอบด้วยรายการเครื่องดื่ม"

    DrinkItem {
        string id PK "รหัส CUID ของเครื่องดื่ม"
        int no UK "ลำดับที่ (1 ถึง 41)"
        string name "ชื่อเครื่องดื่ม (เช่น แบล็ค, ลีโอ)"
        string category "หมวดหมู่ (whisky, beer, soju, ฯลฯ)"
        string unit "หน่วยนับ (ขวด, กระป๋อง, ลัง)"
        int broughtForward "ยอดยกมา (A)"
        int added "สั่งเพิ่ม (B)"
        int cFront "รวมร้านเปิด - หน้าร้าน"
        int cBack "รวมร้านเปิด - หลังร้าน"
        int dFront "คงเหลือร้านปิด - หน้าร้าน"
        int dBack "คงเหลือร้านปิด - หลังร้าน"
        string remark "หมายเหตุพิเศษ"
        datetime createdAt "วันที่สร้างรายการ"
        datetime updatedAt "วันที่แก้ไขล่าสุด"
    }

    DailyShift {
        string id PK "รหัส CUID ของรอบกะ"
        string shiftDate "วันที่ของกะ (YYYY-MM-DD)"
        datetime closedAt "เวลาที่กดปิดยอด"
        int totalSold "ยอดขายรวมทั้งร้าน (E)"
        int totalOpenStock "สต็อกเปิดร้านรวม (C)"
        int totalCloseStock "สต็อกคงเหลือปิดร้านรวม (D)"
        int warningCount "จำนวนจุดเตือนยอดไม่ตรง"
        string notes "หมายเหตุสรุปกะ"
    }

    ShiftRecord {
        string id PK "รหัส CUID ของเรคคอร์ดสแนปช็อต"
        string shiftId FK "อ้างอิง DailyShift.id"
        string drinkId FK "อ้างอิง DrinkItem.id (Nullable)"
        string drinkName "ชื่อเครื่องดื่ม ณ ขณะปิดกะ"
        string category "หมวดหมู่ ณ ขณะปิดกะ"
        int broughtForward "ยอดยกมา (A) ณ วันนั้น"
        int added "สั่งเพิ่ม (B) ณ วันนั้น"
        int cTotal "รวมเปิด (C) ณ วันนั้น"
        int dTotal "คงเหลือปิด (D) ณ วันนั้น"
        int sold "ยอดขาย (E) ณ วันนั้น"
        string remark "หมายเหตุ ณ วันนั้น"
    }
```

## 2. เหตุผลและหลักการออกแบบฐานข้อมูล (Design Rationale)

1. **การแยก Current State กับ Snapshot History:**
   - ตาราง `DrinkItem` จะถูกอัปเดตตลอดเวลาเมื่อมีการนับขวดหรือปิดยอดกะ
   - แต่ตาราง `DailyShift` และ `ShiftRecord` จะทำหน้าที่เป็น **Immutable Snapshot (ข้อมูลประวัติที่ไม่ถูกแก้ไข)** ทุกครั้งที่มีการกดปิดยอดประจำวัน
2. **การรักษาข้อมูลในอดีต (Referential Integrity with `SetNull`):**
   - หากในอนาคตทางร้านมีการลบรายการสินค้าใน `DrinkItem` (เช่น เลิกขายเบียร์บางยี่ห้อ) คีย์ `drinkId` ในตาราง `ShiftRecord` จะถูกเปลี่ยนเป็น `NULL` (`onDelete: SetNull`) แต่ชื่อสินค้า `drinkName` และตัวเลขยอดขายในอดีตจะยังคงถูกเก็บรักษาไว้อย่างสมบูรณ์ ไม่สูญหาย
3. **ประสิทธิภาพในการสืบค้น (Indexing & Ordering):**
   - ฟิลด์ `DrinkItem.no` ถูกกำหนดให้เป็น **Unique Constraint** เพื่อรับประกันความถูกต้องของการเรียงลำดับเครื่องดื่มบนหน้าเว็บ
   - ฟิลด์ `DailyShift.closedAt` ถูกทำ Index เพื่อให้การดึงประวัติกะย้อนหลังทำได้อย่างรวดเร็ว
