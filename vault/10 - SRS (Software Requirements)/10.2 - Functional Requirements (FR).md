## 1. ตารางโครงสร้างข้อมูลและฟิลด์ (Data Columns Specification)

ระบบต้องมีคอลัมน์และช่องกรอกข้อมูลตามลำดับดังต่อไปนี้:

| ลำดับฟิลด์ | ชื่อฟิลด์ (ไทย) | Field Name (EN) | ประเภทข้อมูล (Type) | หน้าที่และการทำงาน |
| :---: | :--- | :--- | :--- | :--- |
| **1** | **ลำดับ** | No. | ตัวเลข (Integer) | เลขลำดับของรายการ ตรึงอยู่กับที่เมื่อเลื่อนตาราง (Sticky Column) |
| **2** | **รายการ** | Item Name | ข้อความ (String) | ชื่อเครื่องดื่ม ตรึงอยู่กับที่ (Sticky Column) พร้อม Badge แสดงหมวดหมู่ |
| **3** | **(A) ยอดยกมา** | Brought Forward | ตัวเลข (Numeric Input) | สต็อกคงเหลือเดิมที่ยกมาจากรอบก่อนหน้า |
| **4** | **(B) สั่งเพิ่ม** | Added | ตัวเลข (Numeric Input) | จำนวนสินค้าที่รับเข้ามาใหม่ในระหว่างกะ |
| **5** | **(C) รวมร้านเปิด** | Total Open | คำนวณอัตโนมัติ (Computed) | มี 2 ช่องย่อย: **หน้าร้าน** และ **หลังร้าน**<br>$$\mathbf{(C) = หน้าร้าน + หลังร้าน}$$ |
| **6** | **(D) คงเหลือร้านปิด** | Total Close | คำนวณอัตโนมัติ (Computed) | มี 2 ช่องย่อย: **หน้าร้าน** และ **หลังร้าน**<br>$$\mathbf{(D) = หน้าร้าน + หลังร้าน}$$ |
| **7** | **(E) ขาย** | Sold | คำนวณอัตโนมัติ (Computed) | ไฮไลท์เรืองแสง Neon Emerald<br>$$\mathbf{(E) = (C) - (D)}$$ |
| **8** | **หมายเหตุ** | Remark | ข้อความ (Text Input) | บันทึกข้อความเพิ่มเติม เช่น "เปิด VIP", "แตกชำรุด", "ขวดแถม" |

## 2. ตรรกะและสมการคำนวณอัตโนมัติ (Auto-Calculation Logic)

```mermaid
flowchart LR
    subgraph Inputs["1. ข้อมูลนำเข้า (Inputs)"]
        A["(A) ยอดยกมา"]
        B["(B) สั่งเพิ่ม"]
        C_front["หน้าร้าน (เปิด)"]
        C_back["หลังร้าน (เปิด)"]
        D_front["หน้าร้าน (ปิด)"]
        D_back["หลังร้าน (ปิด)"]
    end

    subgraph AutoCalc["2. คำนวณอัตโนมัติ (Auto-Calculations)"]
        C["(C) รวมร้านเปิด<br>หน้าร้าน + หลังร้าน"]
        D["(D) คงเหลือร้านปิด<br>หน้าร้าน + หลังร้าน"]
        E["⭐ (E) ยอดขาย<br>(C) - (D)"]
    end

    subgraph Validation["3. ระบบตรวจสอบ (Validation)"]
        Compare{"(A) + (B) == (C) ?"}
        Valid["✅ สต็อกเปิดสมดุล"]
        Warn["⚠️ แจ้งเตือนยอดไม่ตรง<br>(Mismatch Warning)"]
    end

    C_front & C_back --> C
    D_front & D_back --> D
    C & D --> E

    A & B --> Compare
    C --> Compare
    Compare -- เท่ากัน --> Valid
    Compare -- ไม่เท่ากัน --> Warn
```

### รายละเอียดสมการ:
1. **สมการรวมร้านเปิด (Total Open):**
   $$(C) = C_{front} + C_{back}$$
   - เมื่อผู้ใช้พิมพ์ตัวเลขในช่อง `หน้าร้าน` หรือ `หลังร้าน` ระบบจะรวมผลลัพธ์เป็นค่า $(C)$ ทันทีแบบ Real-time
2. **สมการคงเหลือร้านปิด (Total Close):**
   $$(D) = D_{front} + D_{back}$$
   - เมื่อผู้ใช้พิมพ์ตัวเลขในช่อง `หน้าร้าน` หรือ `หลังร้าน` ระบบจะรวมผลลัพธ์เป็นค่า $(D)$ ทันที
3. **สมการยอดขาย (Sold Units):**
   $$(E) = (C) - (D)$$
   - นำยอดรวมเปิดร้าน $(C)$ ลบด้วยยอดคงเหลือปิดร้าน $(D)$ เพื่อหายอดจำนวนขวดที่ขายไปในค่ำคืนนั้น

## 3. ระบบตรวจสอบความถูกต้องของข้อมูล (FR-03: Data Validation)

- **เงื่อนไขการตรวจสอบ (Condition):**
  $$\text{Expected Open} = A + B$$
  $$\text{Actual Open} = C$$
  $$\text{Mismatch Diff} = C - (A + B)$$
- **พฤติกรรมของระบบ (System Behavior):**
  - หากมีการกรอกข้อมูลในช่องสต็อกเปิดร้าน และค่า $C \neq (A + B)$:
    1. ระบบจะแสดง **ไอคอนแจ้งเตือนสีส้มแดง ⚠️ (Warning)** บริเวณกล่องผลรวม $(C)$ ทันที
    2. พื้นหลังแถวจะเปลี่ยนเป็นสีแดงจาง (`bg-rose-950/20`) เพื่อให้สังเกตเห็นได้ง่าย
    3. เมื่อนำเมาส์ชี้หรือแตะที่ไอคอน จะแสดง Tooltip แจ้งผลต่างอย่างชัดเจน เช่น:
       - *ยอดเกิน:* `+1` (ยอดนับจริงมากกว่าสต็อกที่มี)
       - *ยอดขาด:* `-2` (ขวดเหล้าอาจหายไปก่อนเปิดร้าน)
    4. ตัวเลขบนการ์ดสรุปด้านบน **"จุดเตือนยอดไม่ตรง"** จะนับจำนวนรายการที่มีปัญหาขึ้นมาอัตโนมัติ

## 5. การสลับโหมดการแสดงผล (FR-05: Dual View Mode)

1. **โหมดตาราง (Table View):**
   - เหมาะสำหรับ iPad, แท็บเล็ตแคชเชียร์, หรือหน้าจอคอมพิวเตอร์
   - แสดงคอลัมน์ครบถ้วน เลื่อนในแนวนอนได้โดยที่คอลัมน์ `#` และ `รายการเครื่องดื่ม` จะตรึงอยู่กับที่ (Sticky)
   - มีแถวสรุปผลรวมท้ายตาราง (Total Footer)
2. **โหมดการ์ดนับเร็วบนมือถือ (Mobile Cards View):**
   - เหมาะสำหรับการถือสมาร์ทโฟนเดินนับขวดในร้านที่มีแสงน้อย
   - แยกแต่ละเครื่องดื่มเป็นการ์ดขนาดใหญ่
   - มีปุ่ม **`[ - ]`** และ **`[ + ]`** ข้างช่องนับหน้าร้านและหลังร้าน แตะเพื่อเพิ่ม/ลดจำนวนได้ด้วยมือเดียว
   - ช่อง **(E) ขาย** แสดงเด่นชัดขนาดใหญ่พิเศษพร้อมไอคอนไฟ 🔥

## 6. การรายงานและส่งออกข้อมูล (FR-06: Reporting & Export)

1. **Instant LINE Report:**
   - กดปุ่ม **"ส่งสรุป LINE"** ระบบจะจัดรูปแบบข้อความสรุปยอดขาย วันที่ เวลา รายการที่ขายได้ และรายการที่ยอดไม่ตรง พร้อมคัดลอกลง Clipboard ทันที
2. **Excel CSV Export:**
   - ส่งออกไฟล์ CSV พร้อมฝัง **UTF-8 BOM (`\uFEFF`)** เปิดใน Microsoft Excel บน Windows ได้ทันทีโดยไม่เป็นภาษาต่างดาว
3. **Print / PDF Slip:**
   - มีชุดสไตล์ `@media print` จัดรูปแบบเอกสารสรุปสต็อกสำหรับพิมพ์ผ่านเครื่องพิมพ์เทอร์มัลหรือบันทึกเป็น PDF

## 7. การบันทึกและดูย้อนหลังยอดรวมเปิด/ปิดร้านหน้า+หลัง (FR-07: Front/Back Historical Persistence)

- **การบันทึกคงอยู่ตลอดเวลา (Persistent Storage):**
  - การกรอกข้อมูลในช่องรวมร้านเปิด `หน้าร้าน` ($C_{front}$) + `หลังร้าน` ($C_{back}$) และคงเหลือร้านปิด `หน้าร้าน` ($D_{front}$) + `หลังร้าน` ($D_{back}$) ถูกบันทึกไว้ตลอดเวลาทั้งใน `localStorage` และตารางฐานข้อมูล PostgreSQL (`DrinkItem` และ `ShiftRecord`)
- **การดูย้อนหลังหลังจากการปิดยอด (Historical Shift Review):**
  - เมื่อเปิดหน้าต่าง **"ประวัติการปิดยอดที่ผ่านมา (History Modal)"** ผู้ใช้สามารถคลิกขยายเพื่อดูตัวเลขหน้าร้านและหลังร้านของแต่ละรอบที่ปิดไปแล้วได้ครบถ้วน
  - **โหมดดูข้อมูลย้อนหลังในตารางหลัก (Historical View Mode):** มีปุ่ม **"ดูในตาราง (View in Table)"** เพื่อเปิดแสดงข้อมูลของกะรอบนั้นในตารางใหญ่ พร้อมแถบแจ้งเตือนสีทอง `📅 โหมดดูข้อมูลย้อนหลังรอบวันที่ ...` และปุ่ม **"กลับสู่กะปัจจุบัน"**
  - **การกู้คืนข้อมูล (Restore Shift):** สามารถกดกู้คืนข้อมูลรอบวันที่ต้องการกลับมาเป็นกะปัจจุบันเพื่อแก้ไขปรับปรุงได้
  - **ดาวน์โหลด CSV ย้อนหลัง:** สามารถกดดาวน์โหลดไฟล์ CSV ของกะในอดีตแต่ละรอบได้โดยตรง

## 8. การอัปเดตข้อมูลแบบเรียลไทม์ระหว่างผู้ใช้งาน (FR-08: Multi-User Real-time Sync)

- **การทำงานร่วมกันหลายคน (Collaborative Multi-user Support):**
  - เมื่อมีพนักงานหลายคนเปิดเว็บแอปจากโทรศัพท์มือถือ แท็บเล็ต หรือคอมพิวเตอร์พร้อมกัน ข้อมูลจะถูกซิงค์ตรงกันผ่าน PostgreSQL
- **การดึงข้อมูลแบบอัจฉริยะ (Smart Polling & Conflict Prevention):**
  - ระบบตรวจสอบ `document.activeElement` หากผู้ใช้กำลังพิมพ์ตัวเลขในช่องใด ระบบจะไม่เขียนทับช่องนั้น เพื่อป้องกันปัญหาเคอร์เซอร์เด้งหรือตัวเลขกระตุก ขณะที่ช่องอื่นๆ ที่เพื่อนร่วมงานแก้ไขจะอัปเดตขึ้นบนหน้าจออัตโนมัติภายใน 2.5 วินาที
- **ไฟสถานะออนไลน์ (Live Connection Badge):**
  - แสดงสถานะ `🟢 ออนไลน์ & ซิงค์อัตโนมัติ` บนแถบหัวข้อระบบ

## 9. การนำเข้าข้อมูลผ่านไฟล์ Excel (FR-09: Excel/CSV Import & Upsert)

- **การนำไฟล์ Excel ที่ส่งออกกลับมาใช้งาน (Roundtrip Import):**
  - ผู้ใช้สามารถนำไฟล์ Excel (CSV) ที่ส่งออกจากระบบ นำไปกรอกหรือแก้ไขในคอมพิวเตอร์ แล้วนำไฟล์กลับมาอัปโหลดผ่านปุ่ม **"นำเข้า Excel"** ในระบบได้ทันที
- **การตรวจจับหัวตารางอัตโนมัติ (Header Auto-Mapping):**
  - ระบบรองรับทั้งภาษาไทยและอังกฤษ พร้อมตัด UTF-8 BOM อัตโนมัติ:
    - รายการเครื่องดื่ม (`Item Name`, `name`, `รายการ`)
    - ยอดยกมา (`(A) ยอดยกมา`, `broughtForward`)
    - สั่งเพิ่ม (`(B) สั่งเพิ่ม`, `added`)
    - เปิดหน้าร้าน/หลังร้าน (`(C) รวมร้านเปิด [หน้าร้าน]`, `(C) รวมร้านเปิด [หลังร้าน]`)
    - ปิดหน้าร้าน/หลังร้าน (`(D) คงเหลือร้านปิด [หน้าร้าน]`, `(D) คงเหลือร้านปิด [หลังร้าน]`)
    - หมายเหตุ (`remark`, `หมายเหตุ`)
- **หน้าต่างตรวจสอบตัวอย่าง (Preview Modal):**
  - แสดงจำนวนรายการที่พบในไฟล์ พร้อมตารางพรีวิวตัวเลขก่อนกดยืนยัน
- **การบันทึกแบบ Transaction:**
  - อัปเดตข้อมูลลงฐานข้อมูลผ่าน API `POST /api/drinks/batch-import` โดยทำการ Upsert (เพิ่มหากยังไม่มี / อัปเดตหากมีอยู่แล้ว) ในระดับ Database Transaction
