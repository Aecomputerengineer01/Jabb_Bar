## 1. คำสั่งควบคุมหลัก (Core Docker Commands)

```bash
# 1. เริ่มต้นระบบทั้งหมด (สร้าง Image และเปิด Container ในโหมด Background)
docker compose up --build -d

# 2. ตรวจสอบสถานะการทำงานของคอนเทนเนอร์ทั้ง 3 ตัว
docker compose ps

# 3. ดู Log การทำงานแบบ Real-time (ติดตามข้อผิดพลาด)
docker compose logs -f

# 4. ดู Log เฉพาะ Backend API
docker compose logs -f backend

# 5. ดู Log เฉพาะ Database PostgreSQL
docker compose logs -f postgres

# 6. สั่งรันคำสั่ง Seed ข้อมูล Mockup 41 รายการใน Container Backend
docker compose exec backend node prisma/seed.js

# 7. หยุดการทำงานของระบบ (ข้อมูลสต็อกยังคงปลอดภัยใน Volume)
docker compose down

# 8. หยุดและล้างฐานข้อมูลทั้งหมดกลับเป็นค่าเริ่มต้น (Reset All Data)
docker compose down -v
```

---

## 2. การสำรองและกู้คืนฐานข้อมูล PostgreSQL (Backup & Restore)

### การสำรองข้อมูล (Backup to .sql file):
```bash
docker compose exec -T postgres pg_dump -U jabb_user jabb_bar_db > jabb_bar_backup.sql
```

### การกู้คืนข้อมูล (Restore from .sql file):
```bash
cat jabb_bar_backup.sql | docker compose exec -T postgres psql -U jabb_user -d jabb_bar_db
```

## 3. ปัญหาที่พบบ่อยและวิธีแก้ไข (Troubleshooting Guide)

### ปัญหาที่ 1: `failed to connect to docker API / docker daemon not running`
- **อาการ:** รันคำสั่ง `docker compose up` แล้วแจ้งเตือนว่าไม่สามารถเชื่อมต่อ Docker daemon ได้
- **สาเหตุ:** โปรแกรม Docker Desktop ยังไม่ได้ถูกเปิดใช้งานบน Windows
- **วิธีแก้ไข:**
  1. กดปุ่ม Windows ค้นหาโปรแกรม **"Docker Desktop"** แล้วคลิกเปิด
  2. รอจนไอคอนปลาวาฬที่ Taskbar ขึ้นสถานะสีเขียว (Docker is running)
  3. รันคำสั่ง `docker compose up --build -d` อีกครั้ง

---

### ปัญหาที่ 2: พอร์ตชนกัน `Bind for 0.0.0.0:5432 failed: port is already allocated`
- **อาการ:** ไม่สามารถสตาร์ต Container `jabb_bar_postgres` ได้เนื่องจากพอร์ต 5432 ถูกใช้งานอยู่
- **สาเหตุ:** มีโปรแกรม PostgreSQL ที่ติดตั้งไว้เดิมในเครื่องโฮสต์กำลังรันอยู่บนพอร์ต 5432
- **วิธีแก้ไข:**
  - **ตัวเลือก A:** หยุด Service PostgreSQL ใน Windows Services (`net stop postgresql-x64-16`)
  - **ตัวเลือก B:** เปลี่ยนพอร์ตโฮสต์ใน `docker-compose.yml` เช่น เปลี่ยนจาก `"5432:5432"` เป็น `"5433:5432"`

---

### ปัญหาที่ 3: Backend แจ้งเตือน `Can't reach database server at postgres:5432`
- **อาการ:** คอนเทนเนอร์ Backend รีสตาร์ตตัวเองหรือแสดง Error การเชื่อมต่อฐานข้อมูล
- **สาเหตุ:** PostgreSQL กำลังอยู่ในช่วง Initialize ข้อมูลในวินาทีแรก
- **วิธีแก้ไข:**
  - ใน `docker-compose.yml` ได้ติดตั้ง **Healthcheck** ไว้แล้ว Backend จะรอจนกว่า Postgres จะพร้อมรับการเชื่อมต่อจริง (`service_healthy`) หากต้องการรีสตาร์ตเฉพาะ Backend ให้ใช้คำสั่ง:
    ```bash
    docker compose restart backend
    ```

---

### ปัญหาที่ 4: ต้องการแก้ไขโค้ด Frontend แล้วให้แสดงผลทันทีโดยไม่ต้องรัน Docker
- สามารถใช้โหมด **Local Development** ได้โดยตรง:
  ```bash
  # รันเฉพาะ Backend ใน Docker
  docker compose up -d postgres backend

  # และรัน Frontend บนเครื่องโฮสต์ด้วย Vite HMR รวดเร็วเสี้ยววินาที
  cd frontend
  npm run dev
  ```
